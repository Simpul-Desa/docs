# SIMPUL DESA REST APIs

Seluruh data dan hasil pemodelan analitik pada dasbor SIMPUL DESA disajikan melalui antarmuka REST APIs berbasis HTTP. Halaman ini memuat panduan integrasi dan spesifikasi kontrak dari total 26 endpoint yang dikelompokkan berdasarkan modul fiturnya.

Dokumentasi rujukan untuk setiap endpoint digenerasikan langsung secara otomatis dari skema OpenAPI resmi backend SIMPUL DESA. Berkas spesifikasi lengkapnya juga dapat [diunduh dalam format JSON](/openapi/simpul-desa.json).

## Autentikasi

Untuk mengakses endpoint yang diproteksi, sertakan *Bearer Token* dari sesi Supabase Auth pada *header* HTTP permintaan Anda:

<ContohToken />

Aplikasi klien tidak perlu mengirimkan informasi peran pengguna secara manual. Server API secara mandiri akan mengekstrak klaim identitas (`sub`) dari token JWT, memuat data peran dari tabel profil di basis data, lalu mencocokkannya dengan tingkat hak akses yang dipersyaratkan oleh endpoint terkait.

Jika proses autentikasi atau otorisasi tidak terpenuhi, server akan mengembalikan salah satu dari tiga kode galat berikut:

| Kondisi / Penyebab | Kode Galat | Status HTTP |
|---|---|---|
| Token tidak disertakan dalam *header*, sudah kedaluwarsa, atau tidak valid | `TIDAK_BERWENANG` | 401 |
| Token valid, tetapi peran akun pengguna tidak memenuhi batas minimum hak akses | `PERAN_KURANG` | 403 |
| Kredensial atau konfigurasi layanan autentikasi belum disiapkan pada sisi server | `AUTH_BELUM_SIAP` | 503 |

Setiap pengguna yang mendaftar mandiri (*self-registration*) otomatis memperoleh peran dasar sebagai **tamu**. Tingkat hak akses hanya dapat dinaikkan (*upgrade*) oleh administrator sistem.

## Struktur Standar Respons (Amplop JSON)

Setiap respons JSON dibungkus menggunakan struktur pembungkus (*response envelope*) yang seragam dan konsisten, baik ketika permintaan berhasil maupun saat menemui galat:

**Format Respons Sukses:**
```json
{
  "sukses": true,
  "data": [],
  "galat": null,
  "meta": {"total": 38, "hal": 1, "batas": 50, "parameter": null}
}
```

**Format Respons Galat:**
```json
{
  "sukses": false,
  "data": null,
  "galat": {"kode": "DESA_TIDAK_ADA", "pesan": "desa 3201010001 tidak dikenal"}
}
```

Objek `meta` hanya disertakan pada endpoint yang mengembalikan daftar koleksi data berpaginasi. 

Terdapat tiga jenis respons khusus yang berada di luar amplop ini karena tidak berformat JSON standar:
- **Batas Desa**: Mengembalikan berkas murni GeoJSON (terkompresi pra-gzip).
- **Laporan Desa**: Mengalirkan dokumen berkas biner PDF langsung (`application/pdf`).
- **Dokumentasi OpenAPI**: Menyajikan berkas mentah skema `/openapi.json` serta antarmuka visual Swagger UI `/docs`.

## Parameter Paginasi

Seluruh endpoint yang menyajikan daftar data mendukung parameter paginasi berikut melalui *query parameter*:

| Parameter | Nilai Bawaan (*Default*) | Rentang Nilai yang Diizinkan |
|---|---|---|
| `hal` | 1 | 1 s.d. 10.000 |
| `batas` | 50 | 1 s.d. 500 |

Permintaan dengan nilai di luar batas rentang tersebut akan ditolak oleh server dengan status HTTP 422 dan kode `PARAMETER_TIDAK_VALID`. Jumlah total rekaman data yang tersedia dapat dibaca langsung melalui atribut `meta.total` di dalam amplop respons (bukan melalui *header* HTTP terpisah).

## Pembatasan Laju Permintaan (*Rate Limiting*)

Untuk menjaga stabilitas performa sistem dan mencegah lonjakan lalu lintas yang tidak wajar, server menerapkan kuota batas laju permintaan sebagai berikut:

| Cakupan Endpoint | Kuota Ambang Batas |
|---|---|
| Seluruh endpoint umum | 120 permintaan per menit |
| Asisten Desa | 10 permintaan per menit dan maksimal 200 permintaan per hari (dihitung per pengguna) |

Permintaan yang melampaui batas ambang akan otomatis dijawab dengan status HTTP 429 dan kode galat `TERLALU_BANYAK_PERMINTAAN`.

## Katalog Kode Galat

Nilai atribut `galat.kode` bersifat terstandarisasi dan stabil sehingga dapat diandalkan sebagai acuan percabangan logika (*error handling*) pada aplikasi klien. Sementara itu, teks `galat.pesan` ditujukan sebagai penjelasan deskriptif yang mudah dibaca oleh manusia dan redaksinya dapat disempurnakan sewaktu-waktu.

| Kode Galat | Status HTTP | Deskripsi / Situasi Penyebab |
|---|---|---|
| `PARAMETER_TIDAK_VALID` | 400 · 413 · 415 · 422 | Nilai parameter *query* atau *body* permintaan tidak lolos validasi skema |
| `TIDAK_BERWENANG` | 401 | Token autentikasi tidak disertakan dalam *header*, sudah kedaluwarsa, atau tidak valid |
| `PERAN_KURANG` | 403 | Peran akun pengguna tidak mencukupi batas minimum hak akses yang diwajibkan |
| `AKSI_DITOLAK` | 403 | Tindakan ditolak oleh aturan bisnis server (misalnya mencoba mengubah peran akun sendiri) |
| `PERAN_TIDAK_DIKENAL` | 403 | Nilai peran pada profil pengguna tidak dikenali oleh sistem |
| `TIDAK_DITEMUKAN` | 404 | Sumber daya (*resource*) generik yang diminta tidak ditemukan di server |
| `DESA_TIDAK_ADA` | 404 | Kode wilayah desa (`iddesa`) tidak terdaftar dalam basis data master |
| `WILAYAH_TIDAK_ADA` | 404 | Kode provinsi atau kabupaten yang dituju tidak ditemukan |
| `BERITA_TIDAK_ADA` | 404 | Berkas identitas (`id`) artikel berita tidak ditemukan |
| `PENGGUNA_TIDAK_ADA` | 404 | Rekaman pengguna dengan `id` tersebut tidak ditemukan |
| `METODE_TIDAK_DIIZINKAN` | 405 | Metode HTTP yang digunakan (misalnya POST alih-alih GET) tidak didukung pada jalur terkait |
| `KONFLIK` | 409 | Terjadi benturan status atau kondisi data pada basis data |
| `PEKERJAAN_BERJALAN` | 409 | Operasi sinkronisasi atau pembaruan data sejenis sedang berlangsung di latar belakang |
| `TERLALU_BANYAK_PERMINTAAN` | 429 | Frekuensi pemanggilan endpoint telah melampaui batas laju (*rate limit*) |
| `GALAT_SERVER` | 500 | Terjadi kegagalan internal atau anomali yang tidak terduga pada server |
| `GALAT_LLM` | 502 | Permintaan inferensi kecerdasan buatan mengalami kegagalan pada penyedia layanan LLM |
| `DATA_BELUM_SIAP` | 503 | Berkas artefak model analitik belum selesai dimuat ke memori server |
| `AUTH_BELUM_SIAP` | 503 | Konfigurasi atau kredensial layanan Supabase Auth belum terisi di server |
| `AI_BELUM_SIAP` | 503 | Kunci API atau kredensial integrasi Asisten Desa belum dikonfigurasi di server |

## Kebijakan Cache dan CORS

Server membedakan kebijakan penyimpanan singgahan (*caching*) dan kebijakan akses lintas sumber (*Cross-Origin Resource Sharing / CORS*) ke dalam dua kelompok perlakuan:

### 1. Kebijakan Singgahan (*Cache*)
- **Jalur Data Publik/Anonim** (`/api/wilayah`, `/api/desa`, `/api/model/kartu`, `/api/geo`):
  Respons dilengkapi dengan *header* `ETag` (yang dihitung dari versi salinan data) serta arahan `Cache-Control` publik dengan parameter `max-age`. Apabila klien mengirimkan kembali *header* `If-None-Match` dengan nilai yang cocok, server akan langsung merespons dengan kode **304 Not Modified** tanpa perlu memproses ulang data di *handler*.
- **Jalur Bertoken / Terproteksi** (Peta Peran, Citra Potensi Desa, Jalur Ekonomi, Desa Kembar, Berita Desa, Asisten Desa, Laporan Desa, Administrasi):
  Seluruh respons selalu dilabeli dengan `Cache-Control: private, no-store` demi mencegah kebocoran data terproteksi di perantara singgahan publik, dan tidak pernah mengembalikan status 304.

### 2. Kebijakan Lintas Sumber (*CORS*)
- **Akses Terbuka (*Wildcard Origins*)**:
  Metode `GET` pada jalur publik (`/health`, `/api/wilayah`, `/api/desa`, `/api/model/kartu`, `/api/geo`, `/openapi.json`, dan `/docs`) dibuka untuk seluruh domain asal (*all origins* / `*`), sehingga dapat diakses secara bebas oleh aplikasi eksternal maupun portal mitra.
- **Akses Terbatas (*Restricted Origins*)**:
  Seluruh endpoint di luar daftar tersebut—termasuk semua metode non-`GET` meskipun berada pada jalur publik—hanya diizinkan untuk dipanggil dari domain asal (*origin*) resmi dasbor SIMPUL DESA yang telah didaftarkan dalam konfigurasi lingkungan server.

## Autentikasi

Endpoint bertoken memakai bearer token milik Supabase Auth:

<ContohToken />

Klien tidak mengirim peran. Server membaca `sub` dari token, mengambil peran
akun dari tabel profil, lalu mencocokkannya dengan peran yang diizinkan
endpoint itu. Tiga galat yang muncul di jalur ini:

| Keadaan | Kode | HTTP |
|---|---|---|
| Token tidak dikirim, kedaluwarsa, atau tidak sah | `TIDAK_BERWENANG` | 401 |
| Token sah tetapi peran akun tidak mencukupi | `PERAN_KURANG` | 403 |
| Konfigurasi autentikasi belum terisi di server | `AUTH_BELUM_SIAP` | 503 |

Registrasi mandiri selalu menghasilkan peran tamu, dan hanya admin yang
menaikkannya.

## Amplop respons

Setiap respons JSON dibungkus amplop yang sama, sukses maupun gagal:

```json
{
  "sukses": true,
  "data": [],
  "galat": null,
  "meta": {"total": 38, "hal": 1, "batas": 50, "parameter": null}
}
```

```json
{
  "sukses": false,
  "data": null,
  "galat": {"kode": "DESA_TIDAK_ADA", "pesan": "desa 3201010001 tidak dikenal"}
}
```

`meta` hanya ada pada respons daftar. Tiga respons berada di luar amplop
karena bukan JSON: Batas Desa (GeoJSON), Laporan Desa (PDF), dan `/openapi.json`
beserta `/docs` bawaan FastAPI.

## Paginasi

Endpoint daftar menerima `hal` dan `batas`:

| Parameter | Bawaan | Batas |
|---|---|---|
| `hal` | 1 | 1–10.000 |
| `batas` | 50 | 1–500 |

Nilai di luar rentang dijawab 422 `PARAMETER_TIDAK_VALID`. Cacah total ada di
`meta.total`, bukan di header.

## Batas laju

| Jalur | Ambang |
|---|---|
| Semua endpoint | 120 permintaan/menit |
| Asisten Desa | 10 permintaan/menit dan 200 permintaan/hari, per pengguna |

Melewati ambang menghasilkan 429 `TERLALU_BANYAK_PERMINTAAN`.

## Katalog kode galat

`galat.kode` stabil dan boleh dijadikan cabang logika klien; `galat.pesan`
untuk dibaca manusia dan bisa berubah.

| Kode | HTTP | Arti |
|---|---|---|
| `PARAMETER_TIDAK_VALID` | 400 · 413 · 415 · 422 | Parameter atau body tidak lolos validasi |
| `TIDAK_BERWENANG` | 401 | Token tidak ada, kedaluwarsa, atau tidak sah |
| `PERAN_KURANG` | 403 | Peran akun tidak mencukupi, atau profil belum terdaftar |
| `AKSI_DITOLAK` | 403 | Aksi ditolak aturannya sendiri, mis. mengubah peran diri sendiri |
| `PERAN_TIDAK_DIKENAL` | 403 | Peran pada profil tidak dikenal layanan |
| `TIDAK_DITEMUKAN` | 404 | Sumber daya generik tidak ada |
| `DESA_TIDAK_ADA` | 404 | `iddesa` tidak dikenal |
| `WILAYAH_TIDAK_ADA` | 404 | Kode provinsi atau kabupaten tidak dikenal |
| `BERITA_TIDAK_ADA` | 404 | `id` berita tidak ada |
| `PENGGUNA_TIDAK_ADA` | 404 | `id` pengguna tidak ada |
| `METODE_TIDAK_DIIZINKAN` | 405 | Metode HTTP salah untuk jalur itu |
| `KONFLIK` | 409 | Konflik keadaan generik |
| `PEKERJAAN_BERJALAN` | 409 | Pekerjaan penyegaran lain sedang berjalan |
| `TERLALU_BANYAK_PERMINTAAN` | 429 | Batas laju terlampaui |
| `GALAT_SERVER` | 500 | Galat tak terduga di server |
| `GALAT_LLM` | 502 | Layanan Asisten Desa gagal di sisi penyedia |
| `DATA_BELUM_SIAP` | 503 | Artefak data belum dimuat di server |
| `AUTH_BELUM_SIAP` | 503 | Konfigurasi autentikasi belum terisi |
| `AI_BELUM_SIAP` | 503 | Kunci Asisten Desa belum dikonfigurasi |

## Cache dan CORS

Dua kelas jalur, dengan perlakuan berbeda.

Jalur data anonim (`/api/wilayah`, `/api/desa`, `/api/model/kartu`, `/api/geo`)
dijawab dengan `ETag` yang diturunkan dari versi salinan data, plus
`Cache-Control` publik ber-`max-age`. `If-None-Match` yang cocok dijawab 304
tanpa menjalankan handler.

Jalur bertoken (Peta Peran, Citra Potensi Desa, Jalur Ekonomi, Desa Kembar,
Berita Desa, Asisten Desa, Laporan Desa, Administrasi) selalu distempel
`Cache-Control: private, no-store` dan tidak pernah dijawab 304.

Untuk CORS, permintaan GET pada `/health`, `/api/wilayah`, `/api/desa`,
`/api/model/kartu`, `/api/geo`, `/openapi.json`, dan `/docs` dibuka ke semua
origin. Selebihnya, termasuk seluruh permintaan non-GET bahkan pada jalur
publik, hanya diterima dari origin dasbor yang dikonfigurasi server.
